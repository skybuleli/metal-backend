# 测试体系

> Phase 6 实现。四层金字塔测试体系。

## 测试金字塔

```
        ┌─────────────┐
        │   系统测试    │  ← 完整游戏启动渲染
        │   (3-5 个)   │
       ┌┴─────────────┴┐
       │   集成测试      │  ← 着色器编译管线、C#↔C++ 桥接
       │   (10-15 个)   │
      ┌┴───────────────┴┐
      │   功能测试        │  ← 每个 Metal 模块 API 正确性
      │   (20-30 个)     │
     ┌┴─────────────────┴┐
     │    单元测试         │  ← 工具函数、格式转换、纯逻辑
     │    (30-50 个)       │
    └─────────────────────┘
```

## 测试类型

| 层 | 语言 | 框架 | 覆盖范围 |
|----|------|------|----------|
| 单元测试 | C++ / C# | Catch2 / xUnit | 工具函数、格式映射表 |
| 功能测试 | C++ / C# | Catch2 / xUnit | Metal 模块 API 正确性 |
| 集成测试 | C++ / Python | 自定义 harness | 着色器编译端到端、P/Invoke |
| 系统测试 | C# / Shell | Ryubing 启动脚本 | 完整游戏渲染帧 |

## 运行

```bash
make test              # 所有测试
make test-unit         # 仅单元测试
make test-integration  # 仅集成测试
```

## CI 集成

测试在 GitHub Actions 中自动运行，详见 `.github/workflows/ci.yml`。
