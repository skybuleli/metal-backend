# 会话日志归档规则

本目录保存从 `SESSION_LOG.md` 切出的阶段级历史记录。

## 为什么切片

线性会话日志会越来越长，后期会造成三个问题：

- Agent 读取成本升高，容易把旧结论当作当前事实
- 人类查找关键发现时需要翻流水账
- 技术结论、任务证据、会话审计混在一起，不利于复盘

## 切片方式

采用“按阶段归档，按时间排序”的方式：

- `SESSION_LOG.md`：只保留索引、当前状态摘要、最近 3 到 5 条记录
- `phase-0.md`：Phase 0 完整历史
- `phase-1.md`：Phase 1 完整历史
- 后续阶段新增 `phase-2.md`、`phase-3.md` 等文件

## 信息归宿

| 信息类型 | 写入位置 |
|----------|----------|
| 当前任务和下一步 | `NEXT_TASK.md` |
| 任务状态和证据路径 | `PROGRESS.md` |
| 最近会话摘要 | `SESSION_LOG.md` |
| 阶段完整历史 | `docs/session-logs/phase-*.md` |
| 稳定技术结论 | `docs/*.md` |
| 架构决策 | `blueprint/architecture.md` |

## 维护规则

- 每次会话结束，先在 `SESSION_LOG.md` 追加简短记录
- 当 `SESSION_LOG.md` 超过 5 条记录，把较旧记录迁移到对应 `phase-*.md`
- 归档时保留原始时间顺序
- 重要发现必须同步到对应 `docs/*.md`，不能只存在于会话日志
