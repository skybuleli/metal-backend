# P2 Demo 证据格式

> 读者：执行 Phase 2 Demo 任务的维护者或 Agent。
>
> 目标：让 D1-D8 的“已完成”不仅有代码，还有统一可查的构建日志、运行证据和性能记录。

## 适用范围

本规范适用于：

- `P2.1` 到 `P2.11` 的各级 Demo 实现与运行验证
- `P2.12` 的统一构建与回归入口

`P2.0` 的出口不是跑通某个 Demo，而是先把下面这套证据口径固定下来。

## 最低证据要求

每个 Demo 完成时，至少需要三类证据：

| 类别 | 必需内容 | 建议路径 |
|------|----------|----------|
| 构建日志 | 构建命令、是否成功、关键产物路径 | `docs/evidence/P2.X-build.log` |
| 运行证据 | 截图说明、帧缓冲摘要，或窗口成功启动记录 | `docs/evidence/P2.X-run.log` |
| 元数据 | Demo 名称、阶段、着色器路径、关键开关 | `docs/evidence/P2.X-meta.json` |

如果任务包含性能目标，还必须增加第四类：

| 类别 | 必需内容 | 建议路径 |
|------|----------|----------|
| 性能数据 | FPS、帧时间、样本时长、机器信息 | `docs/evidence/P2.X-perf.json` |

如果任务同时包含窗口预览，还建议增加第五类：

| 类别 | 建议内容 | 建议路径 |
|------|----------|----------|
| 预览窗口 | 窗口启动日志、窗口截图、交互说明（如关闭/切换 Demo） | `docs/evidence/P2.X-window.txt` / `docs/evidence/P2.X-window.png` |

## 命名规则

- 文件名前缀统一使用任务号，例如 `P2.1`、`P2.8`
- 同一任务若包含多次验证，使用时间戳后缀，例如 `P2.1-build-20260612-153000.log`
- 不要把不同 Demo 共用一个笼统的 `demo.log`

## 构建日志要求

构建日志至少要包含：

- 执行命令
- 当前机器环境摘要，例如 `uname -a` 或关键工具版本
- 目标 Demo 名称
- 成功或失败结论
- 关键产物路径，例如可执行文件、`metallib`、纹理资源目录

如果构建失败，也应保留失败日志，不要因为任务未完成就不留痕迹。

## 运行证据要求

运行证据至少满足以下之一：

- 截图文件路径 + 截图时机说明
- 帧缓冲导出文件路径 + 像素格式说明
- 如果当前阶段只有命令行窗口或无头模式，至少要有“窗口已创建 / RenderPass 已执行 / Present 已调用”的日志

对于 D1-D5，优先接受截图或帧缓冲摘要。

如果该任务实现了本地预览窗口，建议同时保留：

- 窗口截图
- `CAMetalLayer` / `Present` 成功日志
- 预览窗口与离屏输出使用同一渲染内容的说明

对于 D6-D8，除截图外，最好补充：

- 使用的着色器来源
- `metallib` 加载是否成功
- 关键渲染通道是否执行，例如 shadow pass、HDR pass、Bloom pass

## 元数据 JSON 字段

建议每个 Demo 至少输出这些字段：

| 字段 | 含义 |
|------|------|
| `task` | 任务号，例如 `P2.3` |
| `demo` | Demo 名称，例如 `D2` |
| `scene` | 当前场景简述 |
| `shader_path` | `handwritten-msl` / `path-a-metallib` |
| `artifacts` | 关键产物路径数组 |
| `notes` | 已知限制或临时说明 |

如果任务和性能相关，再增加：

| 字段 | 含义 |
|------|------|
| `avg_fps` | 平均 FPS |
| `avg_frame_ms` | 平均帧时间 |
| `sample_seconds` | 采样时长 |
| `device` | 设备信息，例如 `Apple M1` |

## 与 PROGRESS.md 的关系

在 `PROGRESS.md` 中将 P2 任务标记为 `✅` 时，证据列必须引用至少一个真实存在的证据路径。

推荐写法：

- `docs/evidence/P2.1-build.log + P2.1-run.log`
- `docs/evidence/P2.8-perf.json：Bloom pass 正常，平均 58fps`

不要只写“验证通过”这种不可追溯描述。

## 当前阶段约束

- `P2.0` 只负责把规则定清楚，不要求补齐所有历史证据
- `P2.1` 起每个新任务都应遵守本规范
- `P2.6a` 起允许在保留离屏证据的前提下增加轻量窗口预览，作为开发体验补充
- `P2.12` 再统一考虑是否增加自动截图、自动帧缓冲导出和回归比对
