# 2D 游戏验收清单

> 读者：负责回归和验收的工程师或 QA
>
> 读后要做的事：从候选列表里选出一批 2D 游戏，按统一顺序在当前 Metal 后端上做启动、画面、稳定性和交互验收
>
> 说明：候选名单来自当前 Homebrew App Store Switch 游戏分类的一个快照，验收前建议再刷新一次列表。

## 1. 目标

这份清单用于验证当前阶段的 Metal 后端是否已经具备“可运行 2D 游戏”的基本能力。重点不在性能极限，而在于：

- 能否正常启动
- 是否能稳定显示 2D 画面
- 滚动、动画、UI 和文字是否正确
- 连续运行时是否出现花屏、黑屏、闪烁、崩溃或明显掉帧

如果只看一遍就想开始验收，可以直接按第 3 节的推荐顺序执行。

## 2. 选型原则

从当前 Homebrew App Store 的 Switch 游戏分类里挑选时，优先考虑这几类：

- 画面以 2D 为主，容易肉眼判断是否渲染正常
- 关卡或场景切换少，便于复现和定位问题
- 有明显的滚动、方块、像素风、文字框或 HUD
- 启动快、输入简单，适合做 smoke test

尽量避免一开始就用 3D 大型游戏、复杂引擎移植或依赖大量外部资源的项目。它们更适合后续压力测试，不适合作为第一批验收样本。

## 3. 推荐清单

### 3.1 Smoke Test

先跑这三款，确认“能起、能画、能输入”。

| 游戏 | 角色 | 重点观察 |
|------|------|----------|
| `TetrisNX` | 最小 2D 检查 | 方块是否正确显示，边框和 HUD 是否稳定 |
| `DinoRunNX` | 快速启动检查 | 横向滚动是否正常，基础动画是否平滑 |
| `Switch Pong` 或 `Pong-NX` | 交互检查 | 画面是否稳定，球体移动是否连续，输入是否灵敏 |

### 3.2 标准验收

这几款更适合当作主用例，能覆盖典型 2D 游戏的视觉特征。

| 游戏 | 角色 | 重点观察 |
|------|------|----------|
| `NXEngine-evo` | 主验收用例 | 横版卷轴、角色动画、文本框、透明混合 |
| `MarioBrosNX` | 平台跳跃用例 | 滚屏、跳跃、像素风精细边缘 |
| `OpenSupaplex` | 规则化 tile 用例 | Tile Map、关卡切换、字体与对齐 |
| `PacManNX` | 迷宫 sprite 用例 | Sprite 运动、路径转向、HUD |

### 3.3 压力补充

前面的用例都过了以后，再用下面几款做补充验证。

| 游戏 | 角色 | 重点观察 |
|------|------|----------|
| `Super-Haxagon` | 高节奏 2D 压力用例 | 高频旋转、快速移动、画面边缘稳定性 |
| `sonic3air` | 更接近真实商业游戏的 2D/2.5D 用例 | 大量滚动、特效、场景切换 |
| `Funkin' Rewritten` | 节奏游戏用例 | UI、动画节拍、持续帧稳定性 |

## 4. 推荐执行顺序

如果时间有限，按这个顺序跑：

1. `TetrisNX`
2. `DinoRunNX`
3. `Switch Pong`
4. `OpenSupaplex`
5. `PacManNX`
6. `MarioBrosNX`
7. `NXEngine-evo`
8. `Super-Haxagon`

如果只想先做一次最小验收，跑前四个就够了。

## 5. 每个游戏要记录什么

每次验收建议记录以下内容：

- 启动是否成功
- 首屏是否正常显示
- 进入游戏后是否有黑屏、花屏、卡死或闪烁
- 画面是否有明显撕裂、错位、缩放异常
- 输入是否能驱动角色或 UI
- 连续运行 3 到 5 分钟后是否稳定
- 退出时是否崩溃，是否有残留窗口或进程

如果游戏支持窗口模式、分辨率切换或 full screen，建议至少试一次窗口切换。

## 6. 判定标准

建议把结果分成三档：

- `通过`：能稳定启动，基础画面正确，运行过程中没有明显渲染问题
- `部分通过`：能启动，但存在轻微图像问题、偶发闪烁或个别 UI 问题
- `失败`：无法启动、黑屏、崩溃、严重花屏、输入无响应

如果同一类问题在多个游戏上重复出现，优先按“后端共性问题”处理，而不是单独把它记成某个游戏的问题。

## 7. 失败时怎么分流

遇到问题时，先按现象分流：

- 启动阶段就失败：优先看资源加载、窗口创建和 presenter 链路
- 首帧正常、进入游戏后异常：优先看纹理上传、绘制、混合和深度状态
- 只有滚动或切屏时出问题：优先看交换链、帧同步和尺寸变化
- 字体或 HUD 错乱：优先看像素格式、采样器、裁剪和色彩空间
- 只在长时间运行后出问题：优先看命令提交、同步和资源释放

## 8. 推荐结论

如果目标是快速证明“当前 Metal 后端已经能跑 2D 游戏”，最合适的验证组合是：

- 先用 `TetrisNX` 和 `DinoRunNX` 做 smoke test
- 再用 `OpenSupaplex` 和 `MarioBrosNX` 做标准验收
- 最后用 `NXEngine-evo` 做主用例

这组样本覆盖了方块、滚动、平台跳跃、sprite、文本框和较完整的 2D 场景，是当前阶段最划算的一批验收对象。
