一、DXMT — D3D11→Metal 翻译层

核心可复用组件分析

项目概况
3Shain/dxmt · C++ · 1,087 stars · v0.80 · LGPL
DXMT 是 D3D11/D3D10 到 Metal 的直接翻译层，用于在 macOS/Wine 上运行 3D 应用。相比 DXVK+MoltenVK 的双翻译路径，DXMT 直接将 D3D11 翻译到 Metal，消除了 Vulkan 中间层。

架构分层：
• dxgi/ — DXGI 交换链和适配器
• d3d11/ — D3D11 Device/Context/Resource 完整实现
• dxmt/ — Metal 后端核心（Device/CommandQueue/Buffer/Texture/Presenter）
• airconv/ — DXBC→Metal AIR 着色器编译器
• winemetal/ — Wine 集成层（可选）
可复用组件
① airconv（最核心）
• DXBC（SM5.0）→ LLVM IR → Metal AIR → MetalLib
• 支持 VS/PS/CS/HS/DS/GS 全套着色器阶段
• 曲面细分通过 Mesh Pipeline 模拟
• 几何着色器有专用转换管线
• 命令行工具：HLSL→MetalLib 离线编译

② dxmt Metal 后端
• 完整的 MTLDevice/MTLCommandQueue 管理
• Buffer/Texture/Sampler 生命周期
• Presenter（MetalLayer + HDR + Gamma + MetalFX）
• Fence 同步（MTLFence + intrapass barriers）
• 着色器缓存 + 管线状态缓存

二、deko3d + UAM — Maxwell 硬件知识体系

devkitPro 生态下的 NVN 开源替代方案

deko3d（devkitPro/deko3d · C++ · 394 stars · Zlib）
deko3d 是 fincs 一年多 NVN 逆向工程的结晶，本质上是 Switch 自制软件的 NVN 替代品。

对项目的核心价值：
• engine_3d.def — Maxwell 3D Engine 全部 200+ 寄存器的完整定义。RenderTarget、Viewport、Tessellation、Shader Stage、Zcull 等，每个寄存器都有精确的位域定义。→ NVN→Metal 命令映射的权威参考
• gpu_3d_state.cpp — Maxwell 3D 管线状态机实现
• image_formats.cpp — 像素格式映射表
• dk_shader.h — DKSH 着色器二进制格式规范
• tic_generate.cpp / tsc_generate.cpp — 纹理/采样器控制块生成
UAM（devkitPro/uam · C++ · 25 stars · MIT）
UAM 是基于 Mesa GLSL 解析器 + Nouveau nv50_ir 后端的 Maxwell 着色器编译器。

编译器管线：
GLSL → Mesa GLSL Parser → TGSI IR → nv50_ir → Maxwell GM107 SASS

对项目的核心价值：
• 正向验证：编写 GLSL → UAM 编译 → 获得已知 Maxwell 二进制 → 验证解码器
• 反向理解：nv50_ir 代码展示了每条 GLSL 操作如何映射到 Maxwell 指令
• 双发射调度：基于 karolherbst 的 dual_issue_v3 分支
• 指令编码参考：nv50_ir_emit_gm107.cpp 是 Maxwell 指令编码的权威实现

三、Slang — 多目标着色器编译器

NVIDIA 主导 · 5,364 stars · 支持 GLSL→MSL 直接编译

核心能力
Slang 是 NVIDIA 研究院 5+ 年持续投入的着色器语言和编译器。

支持的输入：Slang 语言（类 HLSL）、HLSL、GLSL（兼容模块）
支持的输出目标：
• D3D12 (DXIL) · D3D11 (HLSL) · Vulkan (SPIR-V)
• 🆕 Metal (MSL) — 实验性但功能完整
• CUDA (C++) · CPU (C++) · WebGPU (WGSL)
Metal 后端详情
Metal MSL 代码生成能力：
• vertex/fragment/compute/mesh 着色器支持
• 系统语义完整映射（SV_Position→[[position]] 等）
• 资源类型映射（ConstantBuffer→constant*, Texture2D→texture2d）
• 插值修饰符映射（nointerpolation→[[flat]] 等）
• 专用 Metal IR 合法化 pass
• 生成人类可读 MSL（保留原始标识符）

Slang 编译管线：
Source → Slang IR → linkAndOptimizeIR → legalizeIRForMetal → MetalSourceEmitter → MSL 文本
🔑 Slang 对项目的决定性价值
Slang 消除了 v1.0 方案中最大的技术风险——自建 Maxwell IR→DXBC 着色器编译器。 因为 Ryujinx 已有 Maxwell→GLSL 管线，Slang 可直接接受 GLSL 输入并生成 MSL。 着色器翻译从"新建编译器（4-6 月）"变为"验证+适配已有管线（1-2 月）"。

五、推荐架构：GLSL-Slang-Metal 直连方案

 └ Maxwell SASS → 结构化 IR

 └ GLSL → Slang IR → MSL
Stage 4: 二进制生成（Apple Metal Compiler）
 └ MSL → MetalLib → GPU 可执行代码

Stage 1: 解析（deko3d engine_3d.def 参考）
 └ NVN 命令缓冲 → Maxwell 寄存器操作
Stage 2: 映射（新建 · 核心工作）
 └ Maxwell 寄存器语义 → Metal API 调用
Stage 3: 执行（Metal Runtime）
 └ MTLCommandBuffer → MTLRenderCommandEncoder
Stage 4: 基础设施（复用 dxmt）
 └ Device/Queue/Buffer/Texture/Presenter

🔬 9.1 反汇编 / 着色器分析工具

T1 envydis
envytools 反汇编器
将 Maxwell SASS（Shader Assembly）二进制反汇编为人类可读的汇编代码。支持 GM107（Maxwell Gen1）ISA 变体。envytools 是 NVIDIA GPU 逆向工程工具集的核心组件。
# 反汇编 Maxwell 着色器二进制 envydis -V gm107 shader_binary.bin # 指定输出文件 envydis -V gm107 shader_binary.bin -o output.asm
关键参数：-V gm107（Maxwell ISA 变体）、-o（输出文件）
安装：git clone https://github.com/envytools/envytools && cd envytools && make
在项目中的角色：Phase 1-4。验证 Maxwell 着色器解码正确性。当渲染结果异常时，用 envydis 查看原始 SASS 确认解码器是否有误。
Agent 调用建议：用于对比验证——将 envydis 输出与 Ryujinx IR 转储对比，确认解码正确性。
T2 nvdisasm
NVIDIA CUDA Toolkit 反汇编器
NVIDIA 官方 GPU 反汇编器，随 CUDA Toolkit 分发。支持 Maxwell 及更新架构。比 envydis 覆盖更广的架构，但为闭源工具。
# 反汇编 cubin/shader 文件 nvdisasm shader.cubin # 显示控制流图 nvdisasm -cfg shader.cubin
安装：随 CUDA Toolkit 安装（brew install cuda 或从 NVIDIA 下载）
在项目中的角色：辅助验证。当 envydis 输出不确定时用作交叉参考。
T3 spirv-dis
SPIRV-Tools 反汇编器
将 SPIR-V 二进制模块反汇编为人类可读的文本格式。属于 Khronos SPIRV-Tools 工具集。
# 反汇编 SPIR-V 二进制 spirv-dis shader.spv -o shader.spvasm # 输出到 stdout spirv-dis shader.spv
安装：brew install spirv-tools 或随 Vulkan SDK 安装
在项目中的角色：Phase 1-4。当通过 SPIR-V 路径验证时，反汇编查看 Slang 或 Ryujinx 生成的 SPIR-V 是否正确。
Agent 调用建议：搭配 spirv-val 使用——先验证合法，再反汇编查看。

⚙️ 9.2 着色器编译 / 转换工具

T4 uam
devkitPro 编译器
GLSL → Maxwell SASS 编译器。基于 Mesa GLSL 解析器 + Nouveau nv50_ir 后端。专为 deko3d API 设计。输出 .dksh 格式着色器模块。支持 Maxwell 双发射调度优化。
# 编译 GLSL 着色器为 deko3d 着色器模块 uam --stage=vert -o output.dksh shader.vert.glsl uam --stage=frag -o output.dksh shader.frag.glsl uam --stage=comp -o output.dksh shader.comp.glsl # 同时输出原始 Maxwell 字节码（用于对比验证） uam --stage=vert -o output.dksh --raw=raw.bin shader.vert.glsl # 同时输出中间 TGSI 代码（调试用） uam --stage=frag -o out.dksh --tgsi=intermediate.tgsi shader.frag.glsl
支持的着色器阶段：vert tess_ctrl tess_eval geom frag comp
安装：devkitPro pacman: (sudo) (dkp-)pacman -S switch-uam
在项目中的角色：核心工具。Phase 1-4。正向验证解码器正确性。编写已知 GLSL → UAM 编译 → 获得参考 Maxwell 二进制 → 与 Ryujinx 缓存中的真实游戏着色器对比。
Agent 调用建议：用于生成测试用例——编写最小 GLSL 着色器，编译为 Maxwell SASS，验证我们的解码器能正确还原为等价 GLSL。
T5 slangc
编译器 核心
Slang 命令行编译器。支持 Slang/HLSL/GLSL 输入，多目标输出（SPIR-V/DXIL/MSL/GLSL/CUDA/C++）。这是连接 Ryujinx GLSL 输出和 Metal MSL 的关键桥梁。
# GLSL → Metal MSL slangc shader.glsl -target metal -entry main -stage vertex -o shader.metal # GLSL → SPIR-V（用于交叉验证） slangc shader.glsl -target vulkan -entry main -stage vertex -o shader.spv # HLSL → Metal MSL slangc shader.hlsl -target metal -entry VSmain -stage vertex -o shader.metal # 带调试信息 slangc shader.glsl -target metal -g -o shader.metal
关键参数：-target metal（Metal MSL 输出）、-entry（入口函数）、-stage（vertex/fragment/compute/mesh）
安装：从 GitHub Releases 下载预编译二进制
在项目中的角色：核心工具。Phase 1-4。着色器翻译管线的核心编译器。Ryujinx GLSL → Slang → MSL → Metal。
Agent 调用建议：每次 Ryujinx 输出 GLSL 后立即调用 slangc 编译为 MSL，检查编译是否成功。
T6 glslangValidator
Khronos glslang 编译器+验证器
Khronos 官方 GLSL→SPIR-V 参考编译器。验证 GLSL 源代码合法性并编译为 SPIR-V。支持 GLSL/HLSL 输入。
# GLSL → SPIR-V glslangValidator -V shader.vert -o shader.vert.spv glslangValidator -V shader.frag -o shader.frag.spv # 仅验证 GLSL（不生成 SPIR-V） glslangValidator shader.vert
安装：brew install glslang 或随 Vulkan SDK 安装
在项目中的角色：Phase 1-4。验证 Ryujinx 输出的 GLSL 代码是合法 GLSL。
Agent 调用建议：每次 Ryujinx 输出 GLSL 后先用 glslangValidator 检查合法性，再传给 Slang。
T7 spirv-cross
Khronos SPIRV-Cross 格式转换
SPIR-V 到多种着色语言的转换器。支持输出 GLSL、HLSL、MSL（Metal Shading Language）、反射 JSON。用于交叉验证 Slang 生成的 MSL 是否正确。
# SPIR-V → Metal MSL spirv-cross shader.spv --msl --output shader_msl.metal # SPIR-V → GLSL spirv-cross shader.spv --output shader.glsl # SPIR-V → 反射信息（用于验证资源绑定） spirv-cross shader.spv --reflect --output reflect.json
安装：brew install spirv-cross 或从 GitHub 构建
在项目中的角色：Phase 1-3。交叉验证工具。将同一 GLSL 通过 glslangValidator→SPIR-V→spirv-cross→MSL 和 Slang→MSL 两条路径对比 MSL 输出质量。
Agent 调用建议：当 Slang 生成 MSL 有问题时，用 spirv-cross 生成替代 MSL 作为参考。

✅ 9.3 验证 / 检查工具

SPIRV-Tools 验证器

Agent 调用建议：每次生成 SPIR-V 后自动调用。退出码非零 = 非法 SPIR-V。
T9 MTL_SHADER_VALIDATION
Apple 运行时验证

# 编译时启用 Metal 着色器验证 export MTL_SHADER_VALIDATION=1 # 或在 Xcode Scheme 中启用： # Product → Scheme → Edit Scheme → Run → Options → Metal Shader Validation
Agent 调用建议：Phase 1-3 始终启用。CI 中强制开启。
T10 MTL_DEBUG_LAYER
Apple API 验证
Apple Metal API 调用验证层。检查 Metal API 的非法使用（资源创建错误、命令编码错误等）。
# 启用 Metal API 调试层 export MTL_DEBUG_LAYER=1
Agent 调用建议：Phase 1-3 始终启用。捕获所有 Metal API 误用。
T11 DXMT 内置验证
dxmt 日志/捕获
DXMT 内置的调试和验证功能。包括日志级别控制、着色器缓存验证、Metal 帧捕获热键。
# DXMT 调试环境变量 export MTL_SHADER_VALIDATION=1 export MTL_DEBUG_LAYER=1 export MTL_CAPTURE_ENABLED=1 export DXMT_CAPTURE_EXECUTABLE="game_executable_name" export DXMT_LOG_LEVEL=debug export DXMT_SHADER_CACHE=0 # 禁用缓存以测试新鲜编译

🐛 9.4 GPU 调试 / 帧捕获工具

T12 Xcode Metal Debugger
Apple 核心
Apple 官方 GPU 调试器。功能包括：GPU 帧捕获、着色器逐行调试、资源检查、性能计数器和时间线。Metal 生态下 RenderDoc 不可用，这是唯一选择。
# 启用 GPU 帧捕获（Xcode Scheme 设置） # Product → Scheme → Edit Scheme → Run → Options # GPU Frame Capture: Enabled # 或在代码中编程式触发捕获 MTLCaptureManager.shared().startCapture(with: device, commandQueue: queue, captureScope: scope)
关键功能：
• 帧捕获后的着色器逐行调试（断点、变量检查）
• 资源绑定检查（纹理、缓冲区内容可视化）
• 性能分析时间线（draw call 耗时排序）
• Shader 编辑后热重载
Agent 调用建议：当渲染结果不正确时，捕获帧 → 定位到问题 draw call → 逐行调试着色器。
T13 Instruments GPU Trace
Apple 性能分析
Apple Instruments 中的 Metal System Trace 模板。提供 CPU+GPU 并行的可视化时间线、内存使用追踪和性能计数器。
# 启动 Instruments instruments -t "Metal System Trace" -D output.trace ./your_app
Agent 调用建议：Phase 3。性能优化时使用，定位 CPU/GPU 瓶颈。
T14 DXMT Metal Capture
dxmt 帧捕获
DXMT 内置的 Metal 帧捕获功能。复用 dxmt Metal 后端时可用。按 F10 热键生成捕获文件。
export DXMT_CAPTURE_EXECUTABLE="game_name" export MTL_CAPTURE_ENABLED=1 # 运行应用，按 F10 捕获当前帧 # 捕获文件保存在可执行文件同目录下
