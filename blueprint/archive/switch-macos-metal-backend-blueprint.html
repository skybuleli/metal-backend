§1 项目简报

📋 一句话定义
为 Ryubing（Ryujinx 活跃分支）开发原生 Apple Metal 图形后端，使 Nintendo Switch 模拟器在 Apple Silicon Mac 上实现硬件加速渲染，摆脱 MoltenVK 间接翻译的性能损失和 SPIRV-Cross MSL 兼容性问题。

1.1 项目动机

问题现状本项目的解决
Ryujinx/Ryubing 的 Metal 支持通过 MoltenVK：Vulkan→SPIRV-Cross→MSL→Metal，双重翻译直接 Maxwell→GLSL→Slang→DXIL→MSC→metallib，单次翻译
SPIRV-Cross MSL 限制7个已知问题：全局变量、描述符集绑定、阴影采样器、控制流、参数缓冲等Path A 完全绕过 SPIRV-Cross；Path C 作为回退
Apple Silicon 未充分利用MetalFX、Argument Buffers Tier 2、TBDR 架构优化未利用原生集成 MetalFX Upscaling/Frame Interpolation、Argument Buffers
现有方案都是标准API翻译D3DMetal/MoltenVK/DXMT/ANGLE 都处理 D3D/Vulkan/OpenGL，无直接处理 Maxwell 的填补 Maxwell→现代API翻译链的最前端空白

1.2 范围边界

✅ 范围内： 着色器翻译管线（Maxwell→Metal）、NVN命令映射（Maxwell寄存器→Metal API）、Ryubing IRenderer/IPipeline 接口实现、MetalFX集成、macOS原生启动器、CI/CD 流水线

❌ 范围外： CPU模拟（复用ARMeilleure）、音频（复用Ryubing）、输入（复用Ryubing）、文件系统（复用Ryubing）、Windows/Linux支持（仅macOS Apple Silicon）

§2 关键架构决策 (Architecture Decision Records)

ADR-001: 着色器翻译主路径 — Slang + MSC

✅ 决定：Path A (Maxwell→GLSL→Slang→DXIL→MSC→metallib) 为主路径
Why not airconv (dxmt)? airconv 吃 DXBC 输入。我们没有 Maxwell→DXBC 编译器。需要从零构建编译器后端，工作量巨大且无现成工具链。

Why not SPIRV-Cross 为主? SPIRV-Cross→MSL 有7个已知缺陷：不支持全局变量、描述符集绑定冲突、阴影采样器语义缺失、控制流"Over 3 compilation loops"错误、未初始化bool变量、参数缓冲基类型推断失败、结构体成员优化删除。SPIRV-Cross MSL被社区认为是"最难的目标语言"。

Why Slang + MSC? Slang 原生支持 -target dxil 输出。MSC 是 Apple 官方维护的 DXIL→metallib 编译器。整条链路每环节都有成熟工具（Ryujinx Decoder→GLSL→Slang→DXIL→MSC→metallib），无需自研任何编译器。MSC 支持 SM 6.0-6.6（含 Ray Tracing、Mesh Shader、Wave Intrinsics）。提供 C API (libmetalirconverter) 可嵌入运行时。

ADR-002: 模拟器基础 — Ryubing (非 Astris)

✅ 决定：基于 Ryubing Fork 开发
Ryubing： 完整开源（MIT），4,813 commits，活跃社区。有清晰的 GAL（Graphics Abstraction Layer），IRenderer/IPipeline 接口天然支持新后端。.NET 10 迁移中。已有 Vulkan/OpenGL/Metal(via MoltenVK) 三个后端实现参考。

Astris： 仅发布二进制（无源码）。605 stars 但不可修改。感谢了 Ryubing 和 Ryujinx 团队——本质是 Ryubing 的 Apple Silicon 预编译优化版。使用 KosmicKrisp (MoltenVK 补丁版) 的间接 Metal 路径。不能用于开发。

集成方式： 创建 src/Ryujinx.Graphics.Metal/ 项目，实现 IRenderer 和 IPipeline 接口，通过 Ryubing 的 GPU 类注册为第4个后端选项。

ADR-003: 语言选择 — C++/C# 混合 + Python/Rust 辅助

✅ 决定：Metal运行时用C++ (metal-cpp)，模拟器集成用C# (Ryubing)，构建脚本用Python，交叉验证用Rust
详见 §3 完整技术栈。

ADR-004: 6条技术路线对比

#路线可行性理由
1 ⭐GLSL→Slang→DXIL→MSC→metallib极高5条子路径，全成熟工具链
2GLSL→Slang→MSL高Slang Metal后端实验性
3GLSL→SPIR-V→SPIRV-Cross→MSL高SPIRV-Cross 7个已知MSL问题
4Maxwell→DXBC→airconv→Metal低无Maxwell→DXBC编译器
5NVN→Vulkan(NVK参考)→MoltenVK→Metal中双重翻译开销
6NVN→D3D11→DXMT→Metal中-低NVN→D3D11语义差距大

§4 着色器管道架构

4.1 5条着色器路径

Maxwell SASS → Ryujinx Decoder → Structured IR → CodeGen/Glsl → GLSL │ ├── Path A (主 ⭐): → Slang -target dxil → DXIL → MSC → metallib │ 优势：Slang DXIL后端成熟 + MSC Apple官方维护 │ ├── Path B (备选): → Slang -target metal → MSL → xcrun metal → metallib │ 优势：纯Apple工具链，零第三方依赖 │ ├── Path C (SPIR-V桥): → glslangValidator → SPIR-V → spirv-opt → SPIRV-Cross → MSL → xcrun metal │ 优势：最成熟的开源路径，经MoltenVK大量验证 │ ├── Path D (SPIR-V优化): → Slang -target spirv → SPIR-V → spirv-opt → Slang -target dxil → DXIL → MSC │ 优势：spirv-opt中间优化后送MSC │ └── Path E (交叉验证): → shader-compiler-rs → GLSL' → 任意路径 优势：第二套独立Maxwell解码器，验证Ryujinx Decoder正确性

4.2 回退策略

运行时自动回退链路：
Path A 失败 → 自动回退 Path C → Path C 失败 → 自动回退 Path B → 全部失败 → 报告编译错误并记录着色器

回退时不阻塞渲染： 使用占位着色器（粉色/品红色）标记编译失败的物体，确保游戏不崩溃。

离线编译模式： 首次遇到着色器时尝试所有路径，成功路径记录到缓存index。后续加载直接用缓存路径，避免运行时回退开销。

4.3 Maxwell硬件参考三层体系

Layer 1 — 寄存器级： deko3d engine_3d.def (3D引擎寄存器) + envytools rnndb (全寄存器XML数据库) → 覆盖：MMIO寄存器、FIFO方法、内存结构 Layer 2 — 指令级： NVK Maxwell后端 (Mesa/Vulkan一致性验证) + MaxAs (SASS汇编器) + nvdisasm (NVIDIA官方反汇编) → 覆盖：SASS指令格式、操作码、寄存器编码、控制流 Layer 3 — 着色器级： Ryujinx Decoder (Maxwell→IR) + shader-compiler-rs (Maxwell→GLSL, 交叉验证) → 覆盖：完整着色器程序解码、结构化IR生成

9.6 CI/CD 流水线

# .github/workflows/ci.yml — 触发条件：push/PR到develop或main

name: CI

on:
  push:
    branches: [main, develop]
  pull_request:
    branches: [main, develop]

jobs:
  verify-tools:        # Phase 0-1: 验证工具链
    runs-on: macos-latest  # Apple Silicon runner
    steps:
      - uses: actions/checkout@v4
      - run: bash tools/tools-verify.sh

  build-metal-bridge:  # Phase 3+: 构建C++库
    runs-on: macos-latest
    steps:
      - run: cd libmetal_bridge && cmake -B build && cmake --build build

  build-ryubing:       # Phase 3+: 构建C#模拟器
    runs-on: macos-latest
    steps:
      - run: cd ryubing && dotnet build

  test-unit:           # Phase 6: 单元测试
    needs: [build-metal-bridge, build-ryubing]
    steps:
      - run: cd tests/unit && pytest test_maxwell_decode.py
      - run: cd ryubing && dotnet test

  test-integration:    # Phase 6: 集成测试
    needs: [test-unit]
    steps:
      - run: cd tests/integration && pytest test_shader_compile.py

  test-regression:     # Phase 6: 回归测试 (GPU required)
    needs: [test-integration]
    steps:
      - run: cd tests/regression && pytest test_demo_frames.py

  build-demos:         # Phase 2+: 构建所有Demo
    steps:
      - run: for d in demos/d*/; do make -C "$d"; done

  build-release:       # Phase 9: 发布构建
    if: github.ref == 'refs/heads/main'
    needs: [test-regression, build-demos]
    steps:
      - run: make release
